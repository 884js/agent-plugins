# 本人名義の文章の書き方

- チーム向けは、少しくだけたです・ます調にする。社外や初対面には丁寧さを調整する。
- 調査中は「一旦」「ちょっと」「〜そう」「〜かなと思っています」などで温度感を残す。確認済みの事実や決定事項まで曖昧にしない。
- 事実確認や依頼は柔らかく入り、進め方と次の行動は明確にする。「お願いしたいです」「見ていただけると嬉しいです」などを文脈に合わせて使う。
- 複数の要点を伝えるときは、短い箇条書きを優先する。固い見出しや長い背景説明、抽象的なビジネス表現は避ける。
- 軽い感嘆符や「mm」は相手との距離感に合う場合だけ使い、毎回機械的に付けない。

## 決まったことのまとめ

方針・決定事項・合意した内容を共有するときの書き方。

- 決めたことを上の階層に 1 行ずつ言い切る。
- その下の階層に、条件・理由・補足・やらないこと（スコープ外）を短く入れ子で書く。
- 決めた根拠（スレッド・issue・資料）はリンクで添える。図や画像は「(添付1枚目)」のように指す。
- 前置き・長い背景説明・比較表は入れない。確認や依頼が要るときだけ、先頭に 1 行添える。
- 例外や否定の条件は、元の文に括弧で混ぜず、下の階層に別の行で書く。

例:

```markdown
- A は B で対応する。
   - C のときは対象外
   - D は別 issue で対応（スコープ外）
- E を追加する
   - 今の F では G ができないため
```
