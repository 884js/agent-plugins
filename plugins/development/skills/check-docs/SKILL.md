# ドキュメントの更新漏れを確認する

コードの差分から、利用者や開発者が読むドキュメントへの影響を調べる。特定の言語、ディレクトリ構成、クライアントに依存せず、そのリポジトリの文書構成と記載の粒度に合わせる。

## 対象と操作を決める

- 対象リポジトリの `AGENTS.md`、`CLAUDE.md` など、適用される指示を読む。
- 差分の指定がなければ `git diff --cached` を対象にする。指定された差分がある場合はそれを使い、報告にも対象を明記する。
- 「確認」「レビュー」だけの依頼や、操作の指定がない呼び出しではファイルを変更しない。ドキュメントの更新まで依頼されている場合は、その範囲で修正し、合意済みの許可を聞き直さない。
- まず対象の差分の有無を確認する。差分がなければ、別エージェントを起動せずその旨を返す。勝手に未ステージの変更やリポジトリ全体へ対象を広げない。

## 更新要否の判定を1体に任せる

- 親エージェントは対象を決めたら、利用中のクライアントの委譲機能で、読み取り専用の判定担当を1体起動する。モデルや推論強度はこのスキルでは固定しない。
- 判定担当にはリポジトリ、対象の差分・比較先、適用される指示、このスキルの判定手順を渡す。可能なら会話履歴を引き継がないコンテキストを使い、親の予想や「更新不要だと思う」といった結論は渡さない。
- 判定担当は下記の「差分と関連ドキュメントを読む」「更新が必要か判断する」を実施し、**更新必要／更新不要／要確認**を、確認した文書・根拠・不足情報とともに簡潔に返す。ファイルの編集、ステージ、別エージェントへの再委譲は行わない。判定担当として呼ばれた場合は、この返却までで終了する。
- 親は判定中に対象のコードや文書を変更しない。返された根拠を確認して採用し、同じ探索を最初から繰り返さない。要確認や根拠不足の箇所だけ追加で調べ、なお不明なら要確認として残す。
- 対象の差分が途中で変わった場合は、古い結果で修正せず、変わった範囲を確認し直す。
- 委譲機能が使えない、または判定担当が起動できない場合は、親が同じ手順で判定し、その旨を報告する。新しいツールの導入やクライアント設定の変更は行わない。

## 差分と関連ドキュメントを読む

判定担当が、差分と関係のある範囲に絞って行う。親は委譲前に同じ探索を済ませない。

- `git status --short`、`git diff --cached --name-status` と差分本文で、追加・変更・削除・改名を把握する。ファイル一覧だけで更新要否を判断しない。
- コミット対象の状態はインデックスを基準にする。部分ステージされたファイルは、必要に応じて `git show :path` で内容を確認し、作業ツリーだけにある仕様を混ぜない。別の差分が指定されている場合も、対応する比較先の状態を見る。
- ルートや変更箇所に近いREADME、関連する設計・API・設定・運用文書、そこからのリンクをたどる。変更された機能名や設定名で検索し、影響のある文書に絞る。特定の文書パスや除外ディレクトリを決め打ちしない。
- ドキュメント自身の差分も読む。すでに記載されている内容を重複させない。作業ツリーの文書だけが対応済みなら、重ねて編集せず「対応済みだが未ステージ」と報告する。
- 差分や必要な文書を読めない場合、未解決の競合がある場合は、確認できなかった範囲を示す。確認済みとして扱わない。

## 更新が必要か判断する

ファイルの追加か既存ファイルの変更かではなく、文書が伝える内容への影響で判断する。

- 公開API、コマンド、設定値、環境変数、導入・実行・運用手順、構成図や一覧が実装と食い違う場合は更新対象とする。削除・改名された項目や、古くなった例も確認する。
- `SKILL.md` の用途や利用条件が変わる場合は、本文の対象範囲と `description` の利用条件・対象外が合っているか確認する。
- 新しい機能や設定の利用に説明が必要なら、既存の文書の粒度に合わせて不足を指摘する。文書の置き場がない場合も、その不足を報告する。
- 内部のリファクタリング、テスト、見た目だけの変更など、記載内容や利用方法に影響しないものは通常更新しない。逆に、バグ修正でも説明された挙動が変わるなら確認する。
- すべてのファイルや関数を列挙する文書へ作り替えない。既存の一覧が網羅的なのか、代表例なのかも考慮する。
- 意図や仕様が読み取れない場合は「要確認」として根拠と不足情報を示す。推測で説明を書いたり、更新不要と断定したりしない。

## 必要な箇所だけ修正する

更新まで依頼されている場合に、親エージェントが行う。

- 既存の言語、構成、表記、並び順に合わせる。追加に限らず、誤った説明の修正や不要になった記述の削除も行う。
- 文書の置き場がない場合は、依頼の範囲内で必要な文書だけ作成する。
- 作業中の無関係な編集を保つ。未ステージのコードを文書に取り込まず、既存の文書編集と矛盾する箇所は無理に上書きせず報告する。
- 更新後の差分を読み、対象の変更を正しく説明し、無関係な変更を含まないことを確認する。リポジトリに文書用の必須チェックがあれば実行する。
- このスキルを呼び出したことだけを理由に、ソースコードの修正、ステージ、コミット、push、フックの設定は行わない。

## 結果を返す

- 更新漏れがあれば、対象の差分、該当文書、根拠、必要な修正を簡潔に示す。更新した場合は、修正内容と確認結果を返す。
- 未ステージの対応や要確認事項、確認できなかった範囲は分けて示す。
- 対象の差分と関連文書を確認でき、更新漏れも未確認事項もなければ `NO_UPDATE` と返す。差分がない場合は「対象のステージ済み差分なし」など、確認した範囲を添えてその旨を返す。
