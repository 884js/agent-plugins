# PRコメント

- 原文と必要な差分・既存コメントを基に書き、推敲では論点や指摘の強さを変えない。ファイル・行番号を添える場合は実際の対象を確認する。
- レビューは1コメント1論点。発生条件・影響・求める対応が伝わる本文にし、先頭に下表のラベルを一つ付ける。依頼やリポジトリに表記の指定があれば優先する。

| ラベル | 用途 |
| --- | --- |
| `[MUST]` | 確認済みの不具合や必須規約への違反など、マージ前に必要な修正 |
| `[IMO]` | 任意の提案。採用する利点を添える |
| `[NITS]` | 誤字などの軽微な指摘。対応は任意 |
| `[Q]` | 判断に必要な仕様や実装意図を確認する質問 |

- 好みや未確認の懸念を `[MUST]` にしない。返信・報告にはラベルを付けない。
- 返信は元の指摘に対する対応内容・理由・確認結果を書く。一部対応や対応しない判断は、未対応の範囲と理由を示す。
- 検証報告は実行結果と未実行を区別する。最新のPRと異なるコミットや環境で確認した場合は明記する。
- そのまま貼れるコメント本文を返す。投稿・編集は明示的に依頼された範囲で行い、対象と既存コメントを確認して重複を避け、投稿後に本文を読み戻してURLを返す。
